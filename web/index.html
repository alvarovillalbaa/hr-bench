USE IT. INSPECT IT. SHARE THE EVIDENCE.
Run a benchmark of your own.
1. Run and replay
Download the verified source or release archive. Use Node 22 or later. Connect your own adapter through the documented JSON-lines protocol; keep provider credentials in its environment.
node bin/hrbench.mjs list
node bin/hrbench.mjs run --adapter ./my-adapter.mjs --target target.json --out run.json
node bin/hrbench.mjs replay run.json
The target file describes the actual model and settings. A replay confirms the trace and score; it does not independently authenticate a model.
Adapter protocol ↗
2. Publish a measured result
Keep the exact dataset manifest, target configuration, raw model/tool turns, all selected rows and failures. Publish the replayable report with runtime/source evidence and clearly state coverage.
Use the same complete public evaluation cohort for comparisons. Infrastructure failures do not become a score of zero. Oracle and manual controls stay separate from model results.
More tasks and expert-backed cohorts require a new frozen dataset version and documented review. The current suite has no independently expert-validated rows.

HOW TO READ THIS BENCHMARK
Start with a task.
Follow the state.
  1. The goal and fictional source define the work. A fresh episode protects every other record.
  2. Agents use four JSON tools. Rejected writes are atomic; forbidden attempts still count against success.
  3. The grader checks final fields, preserved data and authority. A successful task must finish explicitly.
  4. Reports are replayed from raw outputs. A content hash is integrity, not proof of a model’s identity.
Reference/null controls test the environment. V1 has 24 released tasks; the V2 candidate has 96 source-grounded tasks and no model measurement. Both editions remain synthetic and pending independent HR review. Never pool their scores.
